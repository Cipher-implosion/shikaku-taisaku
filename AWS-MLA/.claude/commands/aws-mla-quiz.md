# AWS MLA 模擬テストスキル

弱点問題を1問ずつ出題し、答え合わせ・解説をするスキルです。テスト終了後に結果を自動保存します。

## 開始手順

スキルが呼ばれたら以下を行ってください。

1. `C:\Users\keiji.fujino.dn\Desktop\AWS-MLA\試験直前対策.md` を読み込み、出題テーマを把握する
2. 下記の「問題バンク」から問題を出題する（ランダムな順序で）
3. 各問題の後に答え合わせ・解説をする
4. 全問終了後またはユーザーが「終了」と言ったら、結果をファイルに保存する

## 出題ルール

- 問題は1問ずつ出題する（次の問題は前の問題の解説が終わってから）
- 選択肢は A/B/C/D または 1/2/3/4 どちらで答えても正解とする
- 正解なら「✅ 正解！」、不正解なら「❌ 不正解」と明示する
- 解説では「なぜその選択肢が正解か」「なぜ他の選択肢が間違いか」を明確にする
- 10問ごとに中間スコアを表示する
- 進捗は「問題 X / 全Y問」の形式で常に表示する

## 結果保存ルール

テスト終了時（全問終了またはユーザーが「終了」「やめる」と言ったとき）に以下を実行する。

1. 以下の形式のファイルを `C:\Users\keiji.fujino.dn\Desktop\AWS-MLA\テスト結果\` に保存する
   - ファイル名: `quiz_YYYY-MM-DD_HH-MM.md`（例: `quiz_2026-06-25_14-30.md`）
   - ディレクトリが存在しない場合は PowerShell で作成してから保存する

2. 保存するファイルの形式:

```
# AWS MLA 模擬テスト結果

実施日時: YYYY年MM月DD日 HH:MM
問題数: X問
正解数: Y問
正解率: ZZ.Z%
```

### Q-AL: EMR スポットインスタンス

**Amazon EMR クラスターで分散データ処理ジョブを開発しています。一時的なインスタンス中断やデータ損失が発生しても問題ありません。なるべく少ないコストでテスト環境を構成する必要があります。**

- A. プライマリ・コア・タスクノードすべてをオンデマンドインスタンスとして実行する
- B. プライマリをオンデマンド、コア・タスクをスポットインスタンスとして実行する
- C. プライマリ・コア・タスクノードすべてをスポットインスタンスとして実行する
- D. プライマリ・コアをオンデマンド、タスクをスポットインスタンスとして実行する

**正解: C**

解説:
- C が正解: テスト目的で中断・データ損失を許容するため、すべてスポットインスタンスにするのが最もコスト効率が良い。
- A が不正解: すべてオンデマンドはコストが最大。
- B が不正解: プライマリのみオンデマンドは標準的な構成だがテスト目的ではコスト過剰。
- D が不正解: 本番では多く使われる構成だが、テスト目的で中断を許容するなら全スポットが最安。

テーマ: コスト最適化

### Q-AP: 高い再現率（疾患の見逃し防止）

**医療研究チームが患者データを使用して重大な疾患を早期検出する ML モデルを構築しています。疾患のある患者をできるだけ見逃さないこと（偽陰性を最小限に抑えること）が最も重要です。**

- A. 高い精度（Precision）
- B. 高い再現率（Recall）
- C. 高い F1 スコア
- D. 高い正解率（Accuracy）

**正解: B**

解説:
- B が正解: Recall = TP÷(TP+FN)。実際に陽性の患者の中でモデルが正しく陽性と予測した割合。偽陰性（疾患がある患者を見逃す）を最小化するには Recall を最大化する。
- A が不正解: Precision は偽陽性（疾患がない患者を誤って陽性と予測）を最小化する指標。
- C が不正解: F1スコアは Precision と Recall のバランス指標。「見逃し厳禁」の場合は Recall を単独で最大化する。
- D が不正解: Accuracy は不均衡データでは「全員正常」と予測するだけで高くなりうるため不適。

テーマ: 評価指標

### Q-AY: IAM

**ある企業では Amazon SageMaker を使用して機械モデルを構築しています。この会社には複数の事業部があります。開発チームのみがトレーニングデータにアクセスできるようにし、それ以外の部署はモデルの算出結果のみにアクセスできるようにしたいと考えています。 この企業では、各従業員がそれぞれの AWS アカウントを保有しています。また、トレーニングデータは Amazon S3 バケットに保存されています。 適切なアクセス権を提供するソリューションはどれですか？**

- A. SageMaker のトレーニングジョブが S3 にアクセスできるようにアクセスコントロールリスト（ACL）を設定します。
- B. 開発チームだけがアクセスできるように設定した VPC 上に S3 バケットをデプロイします。
- C. AWS LakeFormation を作成し、既存の S3 バケットに関連付けます。LakeFormation で機械学習モデルへのアクセスを制御します。
- D. IAM ポリシーを作成し、各部署ごとに構成された IAM グループにアタッチします。

**正解: D**

解説:
IAM ポリシーは AWS リソースへのアクセス制御に最も適した方法である。開発チーム向けにトレーニングデータへのアクセスを許可し、それ以外の部署にはモデルの算出結果のみアクセス可能とすることで要件を満たす。

テーマ: IAM

### Q-AZ: サーバーレス推論

**ある企業が Amazon SageMaker を使用して機械学習モデルをデプロイしています。このモデルは顧客からの推論リクエストを処理します。リクエスト数は一定ではなく、1日1時間程度のピーク時にはリクエストが急増し、その他の時間帯はリクエストが非常に少なくなります。この企業はリクエストを低レイテンシで処理する必要があります。また、この企業はコストを最小限に抑えながら、ピーク時のリクエストにも迅速に対応できる構成を必要としています。 適切なソリューションはどれですか？**

- A. Amazon SageMaker リアルタイム推論エンドポイントを作成し、Auto Scaling を有効にしてスケーリングポリシーを設定します。
- B. Amazon SageMaker サーバーレス推論を使用し、ピークタイムに合わせたプロビジョニングされた同時実行数を設定します。
- C. Amazon SageMaker 非同期推論エンドポイントを使用し、推論リクエストをバッチ処理で処理します。
- D. Amazon ECS コンテナを使用してモデルを AWS Lambda 上にデプロイし、顧客からのリクエストをトリガーにコンテナ環境を実行します。

**正解: B**

解説:
Amazon SageMaker のサーバーレス推論は、サーバー層の管理をマネージド（AWS 側で管理）する推論オプションである。サーバーレス推論では、リクエストがないときにリソースを解放するため、コストを抑えることができる。さらに、プロビジョニングされた同時実行数を設定することで、ピーク時のリクエストに対応できる。

テーマ: サーバーレス推論

### Q-BH: Glue

**ある企業が、AWS Glue を使用してデータ処理パイプラインを構築しています。このパイプラインでは、Amazon S3 に保存された複数のデータセットからデータ型やメタデータを取得し、AWS Glue Data Catalog に保存します。この会社は、予め設定されたルールに基づいて、AWS Glue Data Catalog に保存されているデータをもとに異常値を識別し、必要に応じて自動的にデータをクレンジングする必要があります。また、なるべく少ない実装および運用オーバーヘッドでこれを実現したいと考えています。 これらの要件を効率的に満たすために最適なアプローチは次のうちどれですか？**

- A. AWS Lambda を使ってデータ品質を評価します。
- B. Amazon Managed Service for Apache Flink で変換ロジックを作成します。
- C. AWS Glue Data Quality でルールを作成してデータ品質を評価します。
- D. Amazon Athena を使用してデータにクエリを実行し、異常値を特定します。

**正解: C**

解説:
Glue Data Quality は、AWS Glue に組み込まれた機能のひとつであり、事前に設定されたルールでデータ品質を評価できる。これにより、データスキーマの検証、異常値の検出、範囲外のデータの特定など、データのクレンジングプロセスを自動化することができる。ルールセットを使用することで、メタデータに基づいた動的で柔軟な検証が可能である。

テーマ: Glue

### Q-CZ: Data Wrangler

**ある自動車製造企業では、自社工場の日々の生産データを使用して生産計画モデルを構築しています。生産データは、設備管理、生産管理、倉庫管理などの複数のソースから収集され、それぞれ Amazon S3 バケットに保存されています。欠損値が多く別の車種から生成した中央値で補完する必要があります。また、異常値を検知した場合に機械学習エンジニアに通知し、データ取得からトレーニングまでの一貫したワークフローを自動化したいと考えています。 データの収集からトレーニングまでのプロセスを効率化し、自動化する最適な AWS サービスの組み合わせはどれですか？**

- A. Amazon SageMaker Processing ジョブと AWS Glue を使用して、異常値を検知し、モデルをトレーニングします。
- B. Amazon SageMaker Data Wrangler を使用してデータを前処理し、異常データを検知し、Amazon SageMaker バッチ変換を使用してトレーニングします。
- C. Amazon SageMaker Data Wrangler を使用してデータを収集・前処理し、異常データを検知し、Amazon SageMaker Pipelines を使用してデータ処理からモデルトレーニングまでを自動化します。
- D. Amazon EMR 上に PySpark ジョブを構築してデータを処理し、Amazon SageMaker Training ジョブを使用してトレーニングを実行します。

**正解: C**

解説:
SageMaker Data Wrangler は、データ収集と前処理を提供する機能であり、視覚的なインターフェイスを提供し、異常値を検知することができる。SageMaker Pipelines を使用することで、データの収集からモデルトレーニングまでのプロセスを自動化することができる。この方法が最も運用オーバーヘッドが少なく要件を満たす。バッチ変換はモデル推論に適したサービスであり、トレーニングには使用されない。EMR はクラスターの構築・管理や PySpark スクリプトの作成が必要となり実装と運用の手間が大きい。

テーマ: Data Wrangler

### Q-DK: Lambda

**あるフィンテック企業が、市場の値動きをリアルタイムで取得し、分析するためのシステムを構築しています。このシステムでは、市場データを収集、ストリーミングし、異常な取引を検出する必要があります。購入データは CSV と JSON で構成されています。また、市場が開いている時間帯は処理量が大きいですが、夜間や休日は処理量が小さくなります。 なるべく少ない運用オーバーヘッドとコストでこの要件を満たすソリューションはどれですか？**

- A. Amazon Data Firehose を使用してデータをストリームし、Amazon Redshift でデータを取り込んで、異常を検出するアルゴリズムを実装します。
- B. Amazon Kinesis Data Streams でデータをストリームし、AWS Lambda を使用して異常を検出するアルゴリズムを実装します。
- C. Amazon Kinesis Data Streams でデータをストリームし、Amazon Managed Service for Apache Flink を使用して異常を検出するアルゴリズムを実装します。
- D. Amazon S3 にデータを保存し、Amazon Athena を使用して異常値を検出するアルゴリズムを実装します。

**正解: C**

解説:
Amazon Managed Service for Apache Flink（旧 Amazon Kinesis Data Analytics）はリアルタイムデータを処理するためのサービスである。Amazon Kinesis Data Streams などのデータソースからデータを取得し、リアルタイムでデータを処理・変換することができる。Apache Flink には RANDOM_CUT_FOREST などの事前構築された異常検出アルゴリズムがネイティブに統合されており、サーバーレスサービスであるため処理量に応じてスケーリング可能でコスト効率が高い。Data Firehose はデフォルトで60秒のバッファリング間隔があり、Redshift はリアルタイムローディングに適していないため主にバッチ処理に用いられる。Lambda の実行時間には最大15分の制限があり、複雑なアルゴリズムの実装には適していない。S3 と Athena の組み合わせはバッチ処理向けであり、リアルタイム処理には不向きである。

テーマ: Lambda

### Q-DN: 非同期推論

**ある銀行が Amazon SageMaker を使用して、社内の事務手続きや申請プロセスに関する問い合わせに対する FAQ ボットを作成しています。このモデルは、リクエストに対して数秒以内のレスポンスが求められます。ピーク時には秒間数百リクエストが発生しますが、非ピーク時にはリクエストがほとんど発生しません。ピーク時のトラフィック増加に対応するために、エンドポイントの計算リソースを自動的にスケールアウトする必要があります。 推論エンドポイントの可用性を維持しつつ、スケーリングを管理する要件を満たすために、どの機能を使用すべきですか？**

- A. Amazon SageMaker バッチ変換エンドポイントを実装し、エンドポイントの自動スケーリングを有効にします。
- B. Amazon SageMaker 非同期推論を実装し、エンドポイントの自動スケーリングを有効にします。
- C. Amazon SageMaker リアルタイム推論を実装し、エンドポイントの自動スケーリングを有効にします。
- D. Amazon SageMaker リアルタイム推論を実装し、AWS Lambda 上にエンドポイントをデプロイします。

**正解: C**

解説:
Amazon SageMaker リアルタイム推論は、ミリ秒から数秒以内の低レイテンシを求められるユースケースに対応するサービスである。自動スケーリングを設定することで、トラフィックが増加した時にはインスタンスをスケールアウト（増加）、トラフィック減少時にはスケールイン（削減）することで対応可能である。バッチ変換は一定の時間間隔またはデータ量をグループ化してバッチ処理を実行するユースケースに適しており、リアルタイム応答には向いていない。非同期推論はリクエストをキューに入れて逐次処理するため、応答が数秒以内に必要なリアルタイム推論には不向きである。Lambda は秒間数百リクエストの高負荷でスケーリング制限が発生する可能性があり、SageMaker ネイティブな機能に比べて実装・運用オーバーヘッドが大きい。

テーマ: 非同期推論

## 終了処理の手順

全問または「終了」を受け取ったら：

1. スコアサマリーを表示する
2. 不正解だった問題の一覧を表示する
3. PowerShell で `New-Item -ItemType Directory -Force "C:\Users\keiji.fujino.dn\Desktop\AWS-MLA\テスト結果"` を実行してディレクトリを作成する
4. 現在日時を `(Get-Date -Format 'yyyy-MM-dd_HH-mm')` で取得する
5. 結果ファイルを Write ツールで保存する
6. 「結果を保存しました: [ファイルパス]」と伝える
