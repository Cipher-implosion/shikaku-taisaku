# 第2回 演習テスト

## 問題1

> ある企業が、Amazon SageMaker を使用して、機械学習モデルを運用しています。この企業は、機械学習モデルを監視するための機能を探しています。そこでこの会社は SageMaker Model Monitor を設定してモデルを監視することを決めました。
>
> 次のうち、ベースラインを正しく構築および使用するために適切な手順はどれですか？

- A. 運用データの最初のバッチをそのままベースラインとして使用し、Model Monitor で監視ジョブを実行します。
- ✅ B. モデルをトレーニングする際に使用したデータセットのスキーマと統計情報を収集し、ベースラインとして設定します。
- C. Amazon SageMaker Pipelines を使用してベースラインの自動更新をスケジュールします。
- D. 運用データの統計を手動で計算してベースラインを保存します。

**解説**:
Amazon SageMaker Model Monitor は、運用中の機械学習モデルのパフォーマンスやデータ品質を継続的に監視する機能である。運用環境で使用されるデータがモデルのトレーニングデータと一致しているかを評価し、データのドリフトや品質の低下、モデルの性能問題を検出できる。

ベースラインは、Model Monitor がデータやモデルの問題を検出するために使用する基準である。モデルのトレーニングデータを基にして作成され、運用データと比較する際のリファレンス（参照点）として機能する。

## 問題2

> ある企業が Amazon SageMaker を使用して、大量の画像データを処理する機械学習モデルをデプロイしています。このエンドポイントは一度に多くの推論リクエストを処理する必要があります。リクエスト量は日中は多くなり、夜間や休日は低くなる傾向があります。この会社は、需要が低い時間帯ではコストを抑える必要があります。
>
> この要件を満たすために、最適な構成はどれですか？

- A. リアルタイム変換推論エンドポイントを作成します。リクエスト量に応じてインスタンス数を調整する自動スケーリングポリシーを設定します。
- ✅ B. 非同期推論エンドポイントを作成します。リクエスト量に応じてインスタンス数を調整する自動スケーリングポリシーを設定します。
- C. Amazon API Gateway を推論エンドポイントとして使用し、AWS Lambda 関数を統合してリクエスト量を調整します。
- D. AWS Fargate タイプの Amazon ECS コンテナ上に推論エンドポイントを作成します。

**解説**:
非同期推論エンドポイントは、大量のバッチ処理や非同期処理に適している。リクエストをいったんキューに入れて待機させることで、Amazon SageMaker モデルに負荷をかけず、スムーズに推論処理を実行できる。

適切なメトリクス（例：ApproximateBacklogPerInstance）を使用してインスタンス数を動的にスケールする自動スケーリングポリシーを設定することで、リクエスト量に応じたスケールアップとスケールダウンが可能となり、コスト削減とパフォーマンス維持の両方を達成できる。

- A. Amazon Rekognition

## 問題4

> ある企業では Amazon SageMaker を使用して機械モデルを構築しています。この会社には複数の事業部があります。開発チームのみがトレーニングデータにアクセスできるようにし、それ以外の部署はモデルの算出結果のみにアクセスできるようにしたいと考えています。
>
> この企業では、各従業員がそれぞれの AWS アカウントを保有しています。また、トレーニングデータは Amazon S3 バケットに保存されています。
>
> 適切なアクセス権を提供するソリューションはどれですか？

- A. SageMaker のトレーニングジョブが S3 にアクセスできるようにアクセスコントロールリスト（ACL）を設定します。
- B. 開発チームだけがアクセスできるように設定した VPC 上に S3 バケットをデプロイします。
- C. AWS LakeFormation を作成し、既存の S3 バケットに関連付けます。LakeFormation で機械学習モデルへのアクセスを制御します。
- ✅ D. IAM ポリシーを作成し、各部署ごとに構成された IAM グループにアタッチします。

**解説**:
IAM ポリシーは AWS リソースへのアクセス制御に最も適した方法である。開発チーム向けにトレーニングデータへのアクセスを許可し、それ以外の部署にはモデルの算出結果のみアクセス可能とすることで要件を満たす。

## 問題5

> ある企業が Amazon SageMaker を使用して機械学習モデルをデプロイしています。このモデルは顧客からの推論リクエストを処理します。リクエスト数は一定ではなく、1日1時間程度のピーク時にはリクエストが急増し、その他の時間帯はリクエストが非常に少なくなります。この企業はリクエストを低レイテンシで処理する必要があります。また、この企業はコストを最小限に抑えながら、ピーク時のリクエストにも迅速に対応できる構成を必要としています。
>
> 適切なソリューションはどれですか？

- A. Amazon SageMaker リアルタイム推論エンドポイントを作成し、Auto Scaling を有効にしてスケーリングポリシーを設定します。
- ✅ B. Amazon SageMaker サーバーレス推論を使用し、ピークタイムに合わせたプロビジョニングされた同時実行数を設定します。
- C. Amazon SageMaker 非同期推論エンドポイントを使用し、推論リクエストをバッチ処理で処理します。
- D. Amazon ECS コンテナを使用してモデルを AWS Lambda 上にデプロイし、顧客からのリクエストをトリガーにコンテナ環境を実行します。

**解説**:
Amazon SageMaker のサーバーレス推論は、サーバー層の管理をマネージド（AWS 側で管理）する推論オプションである。サーバーレス推論では、リクエストがないときにリソースを解放するため、コストを抑えることができる。さらに、プロビジョニングされた同時実行数を設定することで、ピーク時のリクエストに対応できる。

## 問題7

> ある企業が Amazon SageMaker を使用して、大規模な分散トレーニングジョブを実行しています。トレーニングデータは Amazon S3 に保存され、トレーニングインスタンス間で頻繁な通信が必要です。ネットワークレイテンシを最小限に抑え、トレーニングジョブの効率を最大化するために、最適な構成はどれですか？

- A. トレーニングインスタンスを同じ VPC の複数のアベイラビリティゾーン（AZ）に配置します。
- B. トレーニングインスタンスを同じ VPC の異なるリージョンに配置します。
- ✅ C. トレーニングインスタンスを同じ VPC の同じアベイラビリティゾーン（AZ）に配置します。
- D. トレーニングインスタンスを異なる VPC に配置し、VPC ピアリングを設定します。

**解説**:
同じアベイラビリティゾーン（AZ）内にインスタンスを配置することで、低レイテンシの通信が可能になり、分散トレーニングジョブの効率が向上する。AWS では、物理的なリージョンに配置された複数の物理的なデータセンターからサービスを提供している。アベイラビリティゾーン（AZ）は、データセンター内の物理サーバーを論理的に区切った単位であり、異なる AZ 間では僅かなネットワークレイテンシが発生する。ネットワークレイテンシを最小に抑えたい場合、同じ AZ にインスタンスを配置することが推奨される。

## 問題8

> ある企業が、Amazon SageMaker を使用して機械学習モデルをトレーニングしようとしています。この企業は、既に TensorFlow を使用してローカル環境でモデルを構築し、トレーニングするためのスクリプトを作成しています。このスクリプトは、Amazon SageMaker に最小限の変更で移行したいと考えています。
>
> 以下の選択肢の中で、この要件を満たす最適な方法はどれですか？

- A. SageMaker 固有のインターフェイスに従ったコードに変更し、トレーニングジョブを開始します。
- ✅ B. SageMaker スクリプトモードを使用して、既存の TensorFlow スクリプトを Amazon SageMaker にインポートし、環境変数を使用してデータセットの場所を指定します。
- C. TensorFlow スクリプトを SageMaker が提供する事前構築済みのアルゴリズムに変換し、トレーニングを実行します。
- D. 既存の TensorFlow スクリプトを Amazon S3 に保存し、Amazon S3 のイベント通知を使用して自動的にトレーニングジョブを開始します。

**解説**:
スクリプトモードでは、既存の TensorFlow スクリプトを最小限の変更で Amazon SageMaker に移行できる。既存のスクリプトをそのまま使用可能でき、必要に応じて環境変数を活用してデータセットの場所やハイパーパラメーターを指定することができる。スクリプトモードにより、SageMaker 固有の API に依存しない柔軟性が提供される。

## 問題9

> ある企業が、Amazon SageMaker を使用して機械学習モデルをトレーニングしています。この企業は、Amazon S3 に保存されている数十TB規模のトレーニングデータを迅速に処理する必要があります。トレーニングデータは頻繁にアクセスされ、複数の SageMaker インスタンスがデータを同時に使用します。この要件を満たすために、どのストレージソリューションが最適ですか？

- A. Amazon Elastic File System (Amazon EFS) を使用して、トレーニングデータを共有します。
- ✅ B. Amazon FSx for Lustre を使用して、Amazon S3 バケットをリンクし、トレーニングデータを効率的にキャッシュします。
- C. Amazon S3 を直接使用し、S3 Select を有効にしてトレーニングデータを処理します。
- D. Amazon Redshift を使用してトレーニングデータを保存し、SQL クエリでデータを取得します。

**解説**:
FSx for Lustre は、高性能な分散ファイルシステムであり、大規模データの保存に適している。低レイテンシ、高スループットを提供し、Amazon S3 と統合してデータを効率的にキャッシュできる。また、複数のインスタンスにアクセス可能で、分散ファイルシステムにも使用できる。これにより、トレーニングデータへのアクセスが迅速になる。

## 問題10

> ある企業のデータ分析チームが、Amazon S3 に保存された未処理の販売データを分析しています。このデータには、欠損値、不正値、複数の異なるフォーマットで記録された日付が含まれています。データ分析チームは、コードを記述することなくこれらの問題を効率的に解決し、データを視覚的に確認しながらクリーニングしたいと考えています。
>
> この要件を満たす最適な AWS サービスはどれですか？

- A. Amazon EMR サーバーレス上で PySpark ジョブを実行してデータを処理します。
- B. Amazon SageMaker 上で ML モデルをデプロイし、データをロードして処理します。
- ✅ C. AWS Glue DataBrew で必要な品質ルールを設定し、不適切なデータを処理します。
- D. Amazon QuickSight で不適切なデータを処理します。

**解説**:
AWS Glue DataBrew は、ノーコードで視覚的にデータをクリーニングおよび変換できるツールである。欠損値や不正値の処理、日付フォーマットの標準化など、インタラクティブな GUI を通じてデータ変換が可能である。Glue DataBrew は、あらかじめ定義済の変換ルールを使用して、自動的にデータのロードおよび変換を実行でき、運用コストも抑えることができる。

> これらの要件を満たすために、どの AWS サービスの組み合わせが最適ですか？

## 問題12

> ある企業のデータサイエンスチームは、AWS Glue を使用して、機械学習モデルを構築するために数値データを前処理しています。モデルのトレーニングに使用するデータセットの各特徴量はスケールが異なるため、 min-max 正規化を適用して、すべての値を 0 から 1 の範囲に変換することにしました。さらに、このチームはトレーニングデータセットに対して計算された最小値と最大値を保存し、保存された統計を使用して、テストデータセットや将来の予測データにも一貫したスケール変換を適用する必要があります。
>
> この要件を満たす最適なアプローチはどれですか？

- A. テストデータごとに min-max 正規化を再計算し、それぞれ独立した最小値と最大値を使用してスケーリングします。
- ✅ B. トレーニングデータから計算された最小値と最大値を保存し、それをテストデータと予測データの正規化に使用します。
- C. データ全体を結合して min-max 正規化を実施し、トレーニングとテストデータの分割後に正規化を適用します。
- D. データの各バッチに対して独立した最小値と最大値を計算し、そのバッチにのみ正規化を適用します。

**解説**:
min-max 正規化とは、個々のデータポイントと最小値の差を、最大値と最小値の差分で除算することである。トレーニングデータで計算された統計を一貫して使用することで、スケールの整合性を保ち、モデルが期待どおりに動作するようにすることができる。

## 問題13

> ある企業は Amazon SageMaker を使用して機械学習モデルをトレーニングしています。この企業は、既存のデータセットを Amazon FSx for ONTAP ファイルシステムに保存しています。企業のデータエンジニアは、トレーニングジョブでこのデータを効率的に使用するために、Amazon SageMaker と FSx for ONTAP ファイルシステムを統合する方法を検討しています。また、FSx for ONTAP ファイルシステムから SageMaker トレーニングジョブへのデータアクセスを低レイテンシで提供したいと考えています。
>
> この要件を満たす最適な構成を選択してください。

- A. Amazon S3 を SageMaker インスタンスと同じ VPC にデプロイします。データを Amazon S3 に移動し、S3 バケットから SageMaker トレーニングジョブにデータを提供します。
- ✅ B. Amazon FSx for ONTAP ファイルシステムを SageMaker インスタンスと同じ VPC にデプロイします。FSx を SageMaker に直接マウントします。
- C. Amazon FSx for Lustre ファイルシステムを SageMaker インスタンスと同じ VPC にデプロイします。FSx for ONTAP 上のデータを FSx for Lustre に移動します。
- D. Amazon FSx for ONTAP ファイルシステムをデータソースとして使用する SageMaker Pipeline を構築し、SageMaker トレーニングジョブにデータを送信します。

**解説**:
Amazon FSx for ONTAP は、低レイテンシかつ高スループットでデータアクセスを提供するファイルシステムである。SageMaker トレーニングジョブでは、FSx for ONTAP を NFS または SMB プロトコルを介して直接マウントして使用できる。これにより、データ移動を最小化しつつ効率的にトレーニングデータを処理することが可能となる。

## 問題14

> ある企業では、新しいデータが Amazon S3 バケットにアップロードされるたびに、自動的に Amazon SageMaker Pipeline をトリガーして機械学習モデルの再トレーニングを行う仕組みを構築しようとしています。同社は、なるべく少ない運用コストでこれを実現したいと考えています。
>
> この要件を満たすために最適なソリューションはどれですか？

- A. Amazon S3 イベント通知を使用して、SageMaker Pipeline をトリガーします。
- B. Amazon S3 イベント通知を Amazon SQS キューに送信し、AWS Lambda 関数を使用して SageMaker Pipeline をトリガーします。
- ✅ C. Amazon EventBridge ルールを設定し、S3 イベント通知を設定して新しいデータのアップロードを監視して SageMaker Pipeline をトリガーします。
- D. Amazon SageMaker Data Wrangler を使用して、定期的に S3 バケットをスキャンし、データが見つかった場合に Pipeline をトリガーします。

**解説**:
Amazon EventBridge を使用すると、Amazon S3 イベントをトリガーとして、Amazon SageMaker Pipeline を実行できる。この方法では、中間のコンポーネント（例：Lambda 関数や SQS）を使用する必要がなく、直接的かつ効率的な統合が可能である。

## 問題15
