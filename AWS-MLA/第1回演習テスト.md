# 第1回 演習テスト 問題・解説まとめ

## 問題1
**ある企業が Amazon SageMaker を使用して ML モデルを開発しています。複数のデータサイエンティストが共同でモデルを開発およびトレーニングしています。モデルのバージョン管理を行い、開発環境から本番環境への移行を標準化したいと考えています。また、監査とコンプライアンスの要件を満たすために、すべてのモデルの履歴を追跡できる中央リポジトリが必要です。**

- A. Amazon S3
- **B. SageMaker Model Registry** ✅
- C. AWS Glue Data Catalog
- D. Amazon CloudWatch

**解説：** SageMaker Model Registry は、モデルのバージョン管理、監査、およびプロモーション（開発→本番移行）プロセスの標準化を可能にする。モデルの開発からデプロイメントまでのライフサイクルを追跡し、監査やコンプライアンス要件を満たすための履歴記録機能を提供する。S3 はバージョン管理機能を提供しない。Glue Data Catalog はデータのメタデータ管理向け。CloudWatch はモニタリングツール。

## 問題2
**ある企業が連続したトレーニングジョブを頻繁に実行する必要があります。各トレーニングジョブは同じデータセットと設定を使用し、異なるモデルパラメータをテストします。インフラストラクチャの起動時間を最小化し、ジョブ全体の実行時間を短縮するために、どのソリューションを使用すべきですか？**

- **A. SageMaker マネージドウォームプールを使用します** ✅
- B. SageMaker スポットトレーニングを使用します
- C. SageMaker パイプモードを使用します
- D. SageMaker ハイパーパラメータチューニングを使用します

**解説：** SageMaker マネージドウォームプール（Managed Warm Pool）は、トレーニングジョブ完了後もプロビジョニングされたインフラストラクチャを保持・再利用する機能。反復的なジョブのレイテンシを短縮できる。スポットトレーニングはコスト削減向け（起動時間削減ではない）。パイプモードはデータ読み込み時間短縮向け。ハイパーパラメータチューニングはモデル最適化向け。

## 問題3
**複雑な ML ワークフローを自動化し、トレーニング・モデル評価・デプロイメントなどのプロセスを標準化したいと考えています。再現性を確保し、各ステップの出力を保存しながら、効率的にモデルを管理したいと考えています。**

- A. SageMaker Experiments
- **B. SageMaker Pipelines** ✅
- C. SageMaker Processing
- D. Amazon EventBridge

**解説：** SageMaker Pipelines は、ML ワークフローの自動化と標準化のために設計された機能。トレーニング・評価・デプロイメントを自動化し、各ステップの出力を保存・再利用可能にする。パイプラインは DAG（有向非巡回グラフ）によって可視化される。SageMaker Experiments は実験の追跡・整理向け。SageMaker Processing は個々のタスク実行向け。EventBridge はイベント連携サービス。

## 問題4 
**住宅ローンの承認を予測するモデルで、特定の属性（性別・年齢・人種）に基づく偏りを評価し、その結果を説明可能にする機能が必要です。**

- A. SageMaker Debugger
- B. SageMaker Model Monitor　←（誤答）
- **C. SageMaker Clarify** ✅
- D. Amazon Comprehend

**解説：** SageMaker Clarify は、モデルのバイアス検出と説明可能性を提供するツール。特定の属性に対する偏りを評価し、モデルの予測に寄与する要因を明確にする。SageMaker Debugger はトレーニングジョブ中のエラー・非効率検出向け。Model Monitor は本番環境のデータ品質・パフォーマンス監視向け。Amazon Comprehend は NLP サービス。

## 問題5 
**Amazon S3 に大量の未構造化データを保存しています。S3 に保存されているデータのスキーマやテーブル構造を自動的に検出・カタログ化し、イレギュラー値や欠損値を取り除く処理を実行したいと考えています。**

- A. AWS Glue ETL ジョブを作成し、データのスキーマ検出とクレンジング処理を実行します
- **B. AWS Glue Crawler を使用して Data Catalog にメタデータを保存します。AWS Glue DataBrew を使用して、予め設定したルールに基づいてデータクレンジングをします** ✅
- C. Amazon Athena を使用してデータを直接クエリし、不正な値をフィルタリングします　←（誤答）
- D. Amazon SageMaker Processing ジョブを使用してスキーマ検出とデータクレンジングを実行します

**解説：** AWS Glue Crawler はデータソースのスキーマを自動検出し、AWS Glue Data Catalog にメタデータを登録する。AWS Glue DataBrew は GUI ベースのノーコード/ローコードでデータクレンジング機能を提供し、事前ルール設定で不正値・欠損値を処理できる。Athena はカタログ化要件を満たさない。SageMaker Processing は ML データ処理向けで、データカタログ化には不向き。

## 問題6 
**トレーニングデータと推論データの間で一貫性を保つため、共通の特徴量データセットを管理したいと考えています。また、特徴量をバージョン管理し、他のデータサイエンティストやアプリケーションと共有可能にしたいと考えています。**

- A. Amazon S3 を特徴量データの保存場所として使用します
- **B. Amazon SageMaker Feature Store を使用します** ✅
- C. AWS Glue Data Catalog を使用して特徴量を管理します　←（誤答）
- D. Amazon Redshift を使用して特徴量データをクエリします

**解説：** SageMaker Feature Store は、機械学習ワークフローにおいて特徴量データを管理するサービス。トレーニング・推論間の一貫性確保、特徴量の共有・バージョン管理機能を提供する。オンラインストア（低レイテンシ、リアルタイム向け）とオフラインストア（履歴データ、バッチ向け）の2種類がある。S3 はバージョン管理・共有機能を持たない。Glue Data Catalog はメタデータ管理向けで特徴量バージョン管理に非対応。Redshift はデータウェアハウスで ML 特徴量保存には不適。

## 問題7 
**Amazon S3 バケットに新しいトレーニングデータがアップロードされるたびに Amazon SageMaker パイプラインを自動的に起動するソリューションを探しています。最小限の管理コストで実現したいと考えています。**

- **A. S3 イベント通知を Amazon EventBridge ルールに送信し、SageMaker パイプラインをターゲットとして設定します** ✅
- B. S3 イベント通知を AWS Lambda 関数に送信し、Lambda 関数で SageMaker パイプラインを起動します　←（誤答）
- C. SageMaker パイプラインを Amazon CloudWatch イベントルールでスケジュールし、定期的にトレーニングジョブを実行します
- D. S3 バケットにアップロードされたデータを Amazon Kinesis Data Streams にストリーミングし、Kinesis から SageMaker パイプラインを起動します

**解説：** S3 イベント通知を EventBridge に送信し、SageMaker Pipelines をターゲットとして設定することで、最小限の管理コストで自動起動を実現できる。Lambda を使う方法も可能だが、Lambda 関数のコード管理が必要になり運用負荷が増加する。CloudWatch スケジュールは定期実行向けでイベント駆動ではない。Kinesis はリアルタイムストリーミング向けで本シナリオには過剰。

## 問題8 
**Amazon Bedrock の LLM を使用してドキュメントから要約文を生成するアプリケーションを構築しています。LLM の応答の正確性を向上させるために、事前に保存されたドキュメントから関連情報を検索し、それを LLM に渡して応答を生成したいと考えています。**

- A. Embedding を使用して関連情報を抽出します
- **B. ナレッジベースに統合された Retrieval Augmented Generation (RAG) を使用します** ✅
- C. Amazon Textract を使用してドキュメントをテキストに変換します　←（誤答）
- D. トピックモデリングアルゴリズムを使用して要約を生成します

**解説：** Amazon Bedrock のナレッジベースは RAG（検索拡張生成）ワークフローを完全管理し、データの取り込みから検索、プロンプト強化までを一括処理する。外部情報を統合してより高品質な応答を生成できる。Embedding はデータを数値ベクトルに変換する技術で検索・生成とは別概念。Textract は OCR（スキャン画像からテキスト抽出）向け。トピックモデリングは文書のトピック分析手法。

## 問題9
**顧客データを使用して購買行動を予測するモデルを構築しています。年齢データを購買層に分割、性別データを数値形式に変換、購買頻度データを正規化したいと考えています。**

- A. 年齢: One-hot encoding、性別: Label encoding、購買履歴: 標準化
- **B. 年齢: ビニング、性別: One-hot encoding、購買履歴: Min-max 正規化** ✅
- C. 年齢: 平均値補完、性別: One-hot encoding、購買履歴: 正規化なし
- D. 年齢: 標準化、性別: Label encoding、購買履歴: 標準化

**解説：** ビニングは年齢を範囲で分割し購買層を明確化する手法。One-hot encoding はカテゴリカルデータ（性別）をバイナリ形式（男性:[1,0]、女性:[0,1]）に変換し、カテゴリ間に誤った順序関係を導入しない。Min-max 正規化は購買頻度を 0〜1 の範囲にスケールダウンし、スケール差の影響を排除する。Label encoding は順序関係がない二値カテゴリに対して誤解を招く可能性がある。

## 問題10
**複数のデータソースから収集したデータを一元的に管理するデータストレージソリューションを探しています。構造化・半構造化・非構造化データを一元的に保存し、セキュアなデータアクセスとアクセス制御を細かく設定できる方法を探しています。**

- A. Amazon RDS
- **B. AWS Lake Formation** ✅
- C. Amazon DynamoDB
- D. Amazon S3

**解説：** AWS Lake Formation は、構造化・半構造化・非構造化データを一元的に保存できるデータレイクサービス。様々な AWS データソースと統合し、Glue Data Catalog でメタデータを管理。ユーザー・テーブル・カラム単位での詳細なアクセス制御が可能。RDS は構造化データのみ。DynamoDB は NoSQL のキーバリュー型。S3 は細かなアクセス制御やカタログ機能を提供しない。

**顧客情報を含むデータには欠損値や重複値が含まれており、カテゴリカルデータを数値データに変換し、特徴量エンジニアリングを実施したいと考えています。**

- A. Amazon Athena
- **B. Amazon SageMaker Data Wrangler** ✅
- C. AWS Glue Data Catalog
- D. Amazon EMR

**解説：** SageMaker Data Wrangler は、欠損値補完・重複値削除などの一般的な前処理に加え、One-hot encoding/Label encoding などカテゴリカルデータ変換、標準化・正規化・ビニングなどの特徴量エンジニアリングを提供する機械学習特化型データ準備ツール。Athena はクエリベースのデータ分析向け。Glue Data Catalog はメタデータ管理向け。EMR は大規模分散処理向けで過剰。

## 問題12
**購買データに「地域」（北米・ヨーロッパ・アジア）というカテゴリカル変数が含まれ、数値に変換する必要があります。また、不正な値や欠損値がないかを特定して適切な処理を施す必要があります。**

- A. Amazon EMR でカテゴリカル変数変換。Amazon Athena で欠損値変換
- B. AWS Glue でカテゴリカル変数変換。AWS Glue で欠損値変換
- C. AWS Glue でカテゴリカル変数変換。SageMaker Data Wrangler で欠損値変換
- **D. Amazon SageMaker Data Wrangler でカテゴリカル変数変換。さらに SageMaker Data Wrangler で欠損値変換** ✅

**解説：** Data Wrangler 単独で One-hot encoding/Label encoding によるカテゴリカル変数変換と、欠損値・異常値の特定・処理を GUI ベースで完結できる。SageMaker に統合されているため他ツールを組み合わせる必要がなく、一連の処理フローを自動化してトレーニングジョブと連携可能。他の選択肢は複数サービスを組み合わせる必要があり冗長。

## 問題13
**保険会社が不正請求を予測するモデルを構築しています。データセット内の不正請求の割合が約2%と非常に少ないです。不正請求のデータポイントを増やしてモデルが効果的に学習できるようにしたいと考えています。**

- A. Amazon EMR を使用してデータサンプリングを実行します
- B. AWS Glue を使用してデータのオーバーサンプリングを行います
- **C. Amazon SageMaker Data Wrangler を使用してデータをサンプリングおよびクレンジングします** ✅
- D. Amazon Athena を使用してデータセット全体を再構築します

**解説：** SageMaker Data Wrangler は、データのオーバーサンプリング（少数派クラスのサンプル数を増やす）やアンダーサンプリング（多数派クラスを減らす）を提供する。これによりクラスの不均衡を解消し、モデルが偏りに影響されないよう学習できる。EMR は設定が複雑。Glue は ML 特化機能がなく Data Wrangler の方が適切。Athena はサンプリング機能を提供しない。

## 問題14
**製造会社が、稼働率・素材硬度・稼働温度の特徴量から製品の製造時間（数値）を予測するモデルを構築します。特徴量と製造時間の間の線形な関係を前提としています。**

- A. ロジスティック回帰
- **B. 線形回帰** ✅
- C. K-means クラスタリング
- D. ランダムフォレスト

**解説：** 線形回帰は、目的変数が数値で特徴量と目的変数の間に線形関係がある場合に使用する手法。式: y = w1x1 + w2x2 + … + b。ロジスティック回帰は二値分類問題向け（0/1予測）。K-means は教師なし学習のクラスタリング手法。ランダムフォレストは非線形モデルで、線形関係がある場合は線形回帰の方が解釈性が高い。

## 問題15
**クレジットカード不正利用検出モデルで精度が低下し、不正取引の検出率が減少しています。顧客の購買行動の変化など、モデル学習時には存在しなかった新しい取引パターンがデータセット内で観測されました。**

- A. 既存データと新しいデータを分割し、それぞれモデルの再トレーニングを実施します
- **B. モデルの予測と実際のラベルを比較してパフォーマンスの変化をモニタリングします。新しいデータセットを作成し、既存モデルの再トレーニングを実施します** ✅
- C. モデルのハイパーパラメータを調整します
- D. データセットから少数派クラスを除外してモデルを簡素化します

**解説：** モデル学習時点と現在のデータ分布に変化が生じる現象を概念ドリフト（Concept Drift）と呼ぶ。モニタリングで変化を検出し、新しいデータセットを含めた再トレーニングで解消するのが適切。既存データと新データを別々にトレーニングすると過去のパターンを反映できなくなる。ハイパーパラメータ調整は新パターンへの対応にならない。少数派クラス除外は問題を悪化させる。

## 問題16
**SageMaker トレーニングジョブが S3 バケットにアクセスできるようにするため、適切な IAM 設定を構成する必要があります。**

- A. SageMaker トレーニングジョブを実行する IAM ユーザーに、S3 バケットへのフルアクセス権限を直接付与します
- **B. SageMaker トレーニングジョブ用に作成された IAM 実行ロールに、S3 バケットへの必要なアクセス権限を付与します** ✅
- C. SageMaker Studio を操作する IAM ユーザーに、S3 バケットへのアクセス権限を付与します
- D. SageMaker トレーニングジョブに、S3 バケットへアクセスするためのアクセスキーとシークレットキーを直接埋め込みます

**解説：** IAM 実行ロール（Execution Role）は、AWS サービスが他の AWS リソースにアクセスするための権限を付与する IAM ロール。SageMaker に IAM 実行ロールをアタッチし、必要な S3 権限（GetObject, PutObject など）のみを付与するのが最小権限の原則に基づいた適切な設定。IAM ユーザーへの直接付与は不適切（主体がサービスのため）。フルアクセス付与は過剰権限。アクセスキー埋め込みはセキュリティリスク。

## 問題17 
**住宅価格を予測するモデルで、誤差の大きさをわかりやすい単位（価格単位）で表現し、正負の誤差を相殺せず、全ての誤差を均等に評価する必要があります。**

- A. 平均二乗誤差 (MSE)　←（誤答）
- **B. 平均絶対誤差 (MAE)** ✅
- C. 平均偏差
- D. 決定係数 (R²)

**解説：** MAE（Mean Absolute Error）は予測値と実際の値の誤差の絶対値の平均。誤差が同じ単位（価格単位）で表され直感的に理解しやすく、正負の誤差の相殺を防ぐ。MSE は誤差を二乗するため平方単位になり直感的ではなく、大きな誤差に敏感。平均偏差は正負の誤差が相殺される。R² はモデルの説明力（0〜1）を示す指標で誤差の大きさ評価には不適。

## 問題18 
**ニューラルネットワークモデルを訓練中に、トレーニング損失と検証損失の値が周期的に増減し、モデルが収束しない。さらに学習が進むにつれて損失の減少速度が非常に遅くなっています。**

- A. 学習率を増やします
- B. エポック数を増やします　←（誤答）
- C. ドロップアウト率を増やします
- **D. 学習率を減らします** ✅

**解説：** 損失が周期的に増減して収束しないのは、学習率が高すぎて最適点を飛び越えてしまう（オーバーシュート）ことが原因。学習率を下げることで更新ステップが小さくなり、損失関数の最小値に近づきやすくなる。学習率を増やすとさらに悪化する。エポック数増加は収束しない問題の解決にならない（過学習の原因になりうる）。ドロップアウト率増加は過学習防止であり今回の問題とは無関係。

---

## 問題19
**Amazon S3 に大量の列指向型データを Apache Parquet フォーマットで保存しています。最小限の設定と運用管理で高いパフォーマンスを提供するクエリソリューションを採用したいと考えています。**

- A. Amazon RDS にデータをインポートし、SQL クエリを実行します
- B. AWS Glue を使用してデータを変換し、Amazon Redshift にロードしてクエリを実行します
- **C. Amazon Athena を使用して S3 に格納されたデータに直接クエリを実行します** ✅
- D. Amazon EMR を使用して Apache Hive をセットアップし、S3 のデータにクエリを実行します

**解説：** Amazon Athena はサーバーレスで S3 に直接クエリを実行できるクエリサービス。Parquet のような列指向フォーマットに最適化されており、最小限の設定で効率的にクエリを実行できる。RDS はデータ取り込みに追加コストがかかる。Redshift は高性能だがデータロードプロセスが必要で運用負担が増す。EMR は EMR クラスター設定・管理が必要で運用負担が大きい。

## 試験対策サマリー

### よく出るキーワード整理

**SageMaker サービス別用途**
- **Data Wrangler**: データ前処理・特徴量エンジニアリング・画像処理
- **Autopilot**: AutoML（ノーコードでモデル自動構築）
- **JumpStart**: 事前トレーニング済みモデル・サンプルノートブック活用
- **Clarify**: バイアス検出・モデル説明可能性
- **Debugger**: トレーニング中の問題検出（損失・勾配など）
- **Model Monitor**: デプロイ後のデータドリフト・品質監視
- **Feature Store**: 特徴量の一元管理・バージョン管理・共有
- **Model Registry**: モデルのバージョン管理・ライフサイクル管理
- **Pipelines**: ML ワークフロー自動化・標準化
- **Managed Warm Pool**: 連続トレーニングジョブのインフラ起動時間短縮

**評価指標の使い分け**
- **MAE**: 誤差を価格単位などで直感的に表現、均等評価
- **MSE**: 大きな誤差を強調、平方単位
- **Recall（再現率）**: 偽陰性を最小化（見逃しを防ぐ）
- **Precision（適合率）**: 偽陽性を最小化（誤報を防ぐ）
- **F1スコア**: Precision と Recall のバランス
- **Accuracy**: 均一なクラス分布の場合

**推論エンドポイントの使い分け**
- **リアルタイム推論**: 低レイテンシ（ミリ秒）、常時起動
- **サーバーレス推論**: トラフィック変動が大きい・深夜ゼロ等のコスト最適化
- **非同期推論**: リアルタイム不要・大きなリクエスト（最大5GB）
- **バッチ変換**: 大量データの一括処理

**VPC エンドポイント**
- **ゲートウェイ型**: S3・DynamoDB 専用（無料）
- **インターフェイス型**: SageMaker など多数の AWS サービス（有料）
