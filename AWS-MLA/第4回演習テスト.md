# 第4回 演習テスト

## 問題1
> ある研究機関が、遺伝子発現データを用いて特定の疾患を予測する機械学習モデルを構築しています。このデータセットには数千の特徴量が含まれており、すべての特徴量をそのままモデルに使用すると、モデルのトレーニングに時間がかかり、過剰適合（Overfitting）のリスクが高まる可能性があります。
>
> この研究機関は、次元削減を行うことで特徴量の数を減らし、モデルの効率と性能を向上させたいと考えています。次元削減の方法として、以下のうちどれが最適ですか？

- A. ランダムフォレストを使用して特徴量の重要度を計算し、重要度の高い特徴量を選択します
- ✅ B. 主成分分析（PCA）を使用して、相関の高い特徴量をまとめた少数の主成分を生成します
- C. クラスタリングアルゴリズムを使用して、似た特徴量をグループ化します
- D. データ正規化を行い、すべての特徴量を同じスケールに変換します

**解説**:
PCA（Principal Component Analysis）は次元削減に最も広く使用される手法の1つである。特徴量間の相関関係を考慮し、それらを少数の主成分にまとめることで、データの情報を保ちながら次元を削減する。ランダムフォレストは複数の決定木を組み合わせたアンサンブル手法であり、特徴量の寄与度の計算はできるが次元削減の手法ではない。クラスタリングアルゴリズムはデータポイントをグループ化するための手法であり、特徴量を次元削減する手法ではない。データ正規化は特徴量のスケールを揃えてモデルの性能を向上させる手法であり、次元削減ではなくデータ前処理に該当する。

## 問題2
> あるヘルスケア企業が、患者の個人情報（PII: Personally Identifiable Information）を含む大量の医療データを分析しています。この企業は、患者のプライバシーを保護するために、PII を特定し、その情報を削除または匿名化したいと考えています。データは Amazon S3 に保存されており、PII の検出と変換プロセスを自動化する必要があります。
>
> この要件を満たすために、最も適切な AWS サービスとアプローチはどれですか？

- A. AWS Glue クローラーを使用して PII を検出し、Glue ジョブを活用して PII データを Amazon S3 から削除します。
- B. Amazon Macie を使用して PII を検出し、PII データを変換処理します。
- ✅ C. AWS Glue PII Detection Transform を使用して PII データを検出し、変換します。
- D. Amazon SageMaker を使用して PII 検出モデルをトレーニングし、匿名化処理を実装します。

**解説**:
AWS Glue の PII Detection Transform を使用すると、個人情報を自動的に検出し、匿名化または削除するプロセスを設定できる。社会保障番号、電話番号、住所などを検出し、あらかじめ定義したエンティティに沿ってマスキングや削除操作を行うことができる。Glue クローラーはデータソースからスキーマやメタデータを抽出する機能であり、PII の検出機能はない。Amazon Macie は S3 上のデータから PII を検出するサービスだが、データの匿名化や削除等の機能がなく追加プロセスが必要となる。SageMaker でカスタムモデルをトレーニングするには開発・運用コストがかかり、このシナリオでは過剰なアプローチである。

## 問題3
> あるフィンテック企業が機械学習モデルの構築を効率化するために、Amazon SageMaker を利用しています。この企業では、モデルの構築、トレーニング、デプロイを一元的に管理し、データサイエンティストがブラウザベースのインターフェースを利用して作業できる環境を整えたいと考えています。
>
> この要件を満たすために、最適なアプローチは次のうちどれですか？

- ✅ A. Amazon SageMaker Studio Classic を使用して新しいプロジェクトを作成し、統合されたノートブック環境でトレーニングとモデル管理を行います。
- B. Amazon SageMaker Studio Lab を使用してモデルのトレーニングと管理を行います。
- C. AWS Lambda を使用してモデルのトレーニングとデプロイを行います。
- D. Amazon SageMaker Canvas を使用してモデルを構築します。

**解説**:
Amazon SageMaker Studio Classic は、ブラウザベースのインターフェースを提供し、モデルの構築、トレーニング、デプロイを一元的に管理できる統合環境である。ノートブック環境を活用することで、データの可視化、コードの実行、トレーニングジョブの管理、モデルのデプロイを効率的に行うことができる。SageMaker Studio Lab は無料のツールであり、主に個人や小規模プロジェクト向けで商業規模に対応した高度な機能を提供しない。Lambda はサーバーレス関数実行環境であり、機械学習モデルのトレーニングや管理を行う環境ではない。SageMaker Canvas はノーコードでモデルを構築できるツールだが、高度な設定が必要な場合は Studio が適している。

## 問題4
> ある製薬会社が、複数の機械学習モデルの概念実証を行っています。これらのモデルは、異なる薬品開発プロジェクトに使用され、それぞれのプロジェクトでバージョン管理が存在します。モデルには、薬品の検品工程を画像認識するモデル、臨床データを分析する数値解析モデル、販売予測モデルなど、さまざまなアルゴリズムが含まれます。製薬会社では、複数のモデルを保存し、バージョン管理するための機能を探しています。
>
> この要件を満たすために、最適なソリューションは次のうちどれですか？

- A. Amazon S3 にモデルアーティファクトを保存し、各プロジェクトごとにフォルダ構造を作成します。
- B. Amazon SageMaker Model Registry を使用し、モデルごとに新しいエントリを作成してバージョン管理します。
- ✅ C. Amazon SageMaker Model Registry のコレクション機能を使用し、各プロジェクトのモデルを管理します。
- D. AWS Glue Data Catalog を使用し、モデルアーティファクトを管理し、検索可能なデータセットとして登録します。

**解説**:
Model Registry のコレクション機能を使用することで、複数のモデルをプロジェクトごとに整理して管理できる。コレクション内では、モデルのトレーニング履歴や評価結果、バージョン情報を効率的に追跡できる。S3 はオブジェクトストレージだがバージョン管理やモデルのライフサイクルをサポートする機能はなく、フォルダ構造の手動管理は非効率である。Model Registry 単体でのモデルエントリ管理は部分的に正しいが、複数の異なるモデルをまとめて管理するにはコレクション機能の使用が最適である。Glue Data Catalog はデータカタログやメタデータの管理には適しているが、機械学習モデルのバージョン管理やライフサイクル管理には対応していない。

## 問題5
> ある企業が Amazon SageMaker を使用して機械学習モデルをホストしています。このモデルは、特定のクライアントIPアドレスからのみアクセス可能にしたいと考えています。Amazon VPC 内のサブネットに対して特定の IP アドレスからのアクセスのみを許可し、それ以外の IP アドレスからのアクセスを拒否したいと考えています。
>
> 以下のうち、この要件を満たすために正しい構成はどれですか？

- A. SageMaker エンドポイントにセキュリティグループを適用し、指定した IP アドレスを許可し、他のすべてを拒否します。
- ✅ B. ネットワーク ACL のインバウンドルールに指定した IP アドレスからのアクセスを許可し、他のすべてを拒否します。
- C. サブネットのルートテーブルを更新し、指定した IP アドレスをターゲットに設定します。
- D. ネットワーク ACL のアウトバウンドルールに指定した IP アドレスからのアクセスを許可し、他のすべてを拒否します。

**解説**:
ネットワーク ACL はステートレスなファイアウォール機能を提供し、サブネットレベルでトラフィックの許可または拒否を制御する。指定されたクライアント IP アドレスからのアクセスを許可するインバウンドルールと、他のすべての IP アドレスからのアクセスを拒否するデフォルトルールを設定することで要件を満たす。セキュリティグループはステートフルなファイアウォールであり許可ルールのみ設定可能で、本問の要件には不十分であり、サブネットレベルの制御にはネットワーク ACL が適切である。ルートテーブルはトラフィックの送信先を指定するものであり、アクセス制御には使用しない。アウトバウンドルールはサブネット内から外部に送信されるトラフィックを制御するものであり、外部からのアクセス制御にはインバウンドルールが必要である。

## 問題6
> あるオンライン教育プラットフォームが、クリックデータや検索履歴などの学習者の行動ログと、アップロードされた画像やテキストコンテンツを用いて、学習者に最適な講義をレコメンドするシステムを構築しようとしています。
>
> この要件を満たすために、最適な Amazon Bedrock モデルはどれですか？

- A. Titan Text Embeddings
- ✅ B. Titan Multimodal Embeddings
- C. Claude for Text Understanding
- D. Stable Diffusion for Image Generation

**解説**:
Titan Multimodal Embeddings は、テキストデータと画像データの両方を埋め込み（embeddings）として変換することが可能である。これにより、マルチモーダルデータを使用する学習者推薦システムを構築できる。Amazon Titan は AWS が提供するファウンデーションモデル（FMs）のファミリーであり、Titan Text Embeddings（テキストデータを数値ベクトルに変換）や Titan Multimodal Embeddings（テキストと画像のマルチモーダルデータを変換）がある。Titan Text Embeddings はテキストデータの埋め込み生成に適しているが、マルチモーダルデータには対応していない。Claude は自然言語理解を提供するモデルだが画像データには対応していない。Stable Diffusion は画像生成を目的としたモデルであり、埋め込み生成には適していない。

## 問題7
> あるフィンテック企業が、市場の値動きをリアルタイムで取得し、分析するためのシステムを構築しています。このシステムでは、市場データを収集、ストリーミングし、異常な取引を検出する必要があります。購入データは CSV と JSON で構成されています。また、市場が開いている時間帯は処理量が大きいですが、夜間や休日は処理量が小さくなります。
>
> なるべく少ない運用オーバーヘッドとコストでこの要件を満たすソリューションはどれですか？

- A. Amazon Data Firehose を使用してデータをストリームし、Amazon Redshift でデータを取り込んで、異常を検出するアルゴリズムを実装します。
- B. Amazon Kinesis Data Streams でデータをストリームし、AWS Lambda を使用して異常を検出するアルゴリズムを実装します。
- ✅ C. Amazon Kinesis Data Streams でデータをストリームし、Amazon Managed Service for Apache Flink を使用して異常を検出するアルゴリズムを実装します。
- D. Amazon S3 にデータを保存し、Amazon Athena を使用して異常値を検出するアルゴリズムを実装します。

**解説**:
Amazon Managed Service for Apache Flink（旧 Amazon Kinesis Data Analytics）はリアルタイムデータを処理するためのサービスである。Amazon Kinesis Data Streams などのデータソースからデータを取得し、リアルタイムでデータを処理・変換することができる。Apache Flink には RANDOM_CUT_FOREST などの事前構築された異常検出アルゴリズムがネイティブに統合されており、サーバーレスサービスであるため処理量に応じてスケーリング可能でコスト効率が高い。Data Firehose はデフォルトで60秒のバッファリング間隔があり、Redshift はリアルタイムローディングに適していないため主にバッチ処理に用いられる。Lambda の実行時間には最大15分の制限があり、複雑なアルゴリズムの実装には適していない。S3 と Athena の組み合わせはバッチ処理向けであり、リアルタイム処理には不向きである。

## 問題8
> あるオンラインプラットフォームでは、ユーザーがアップロードした画像や動画コンテンツをホストする機能を提供しています。このプラットフォームでは、コミュニティガイドラインに違反する可能性のある不適切なコンテンツ（例：暴力的な画像や成人向けコンテンツ）を検出するための自動化されたシステムを導入したいと考えています。
>
> アップロードされたメディアファイルをリアルタイムでスキャンし、潜在的に不適切なコンテンツを検出する必要があります。この要件を満たす最適な AWS サービスとアプローチはどれですか？

- A. Amazon Rekognition を使用して、DetectLabels API を呼び出し、不適切なコンテンツを検出します。
- ✅ B. Amazon Rekognition を使用して、DetectModerationLabels API を呼び出し、不適切なコンテンツを検出します。
- C. Amazon Rekognition Custom Labels を使用して、事前に定義されたモデルをトレーニングし、不適切なコンテンツを検出します。
- D. Amazon S3 に画像ファイルを保存し、AWS Lambda を使用してコンテンツをレビューします。S3 イベント通知で Lambda 関数をトリガーします。

**解説**:
Rekognition の DetectModerationLabels API は、不適切なコンテンツ（成人向けコンテンツ、暴力的な画像など）を検出する機能であり、アップロードされたメディアをスキャンして自動的に不適切なコンテンツを検出できる。DetectLabels API は画像や動画から一般的なラベル（人間、建物、動物など）を検出するものであり、不適切なコンテンツ検出には使用しない。Rekognition Custom Labels は独自のデータセットを使ってカスタムモデルをトレーニングする機能であり、DetectModerationLabels の機能で十分なこのシナリオでは不要である。Lambda はメモリや実行時間の制限があり、画像・動画検出のような複雑な処理には適していない。

## 問題9
> ある広告代理店企業が Amazon Bedrock を使用して、顧客製品のキャッチコピーを生成するモデルを構築しています。この会社は、自然言語生成モデルを活用して、なるべく多様でクリエイティブなキャッチコピーを作成し、アイデアを創出するためのきっかけにしたいと考えています。
>
> 応答の多様性を向上させるために、最も適切なハイパーパラメータと対応はどれですか？

- A. Temperature パラメータを増やし、Top_k パラメータを減らす
- B. Temperature パラメータを減らし、Top_k パラメータを増やす
- ✅ C. Temperature パラメータと Top_k パラメータを増やす
- D. Temperature パラメータと Top_k パラメータを減らす

**解説**:
Temperature（温度）は、モデルが生成する次の単語の確率分布をスケーリングするパラメータである。高い値にするとランダム性が増し、低い値にすると決定論的な応答になる。Top_k は、モデルが次の単語を選択する際に考慮する単語の候補数を制限するパラメータであり、上位 k 個の単語からランダムに選択する（例：Top_k=1 では常に最も確率が高い単語が選ばれ、Top_k=50 では上位50個からランダムに選ばれる）。応答の多様性を向上させたい場合、Temperature と Top_k の両方を増やすことが適切である。

## 問題10
> ある出版企業は、様々な言語のドキュメントからトピックを抽出し、ドキュメントの要約をグルーピングするモデルを構築しています。このモデルは Amazon SageMaker AI NTM で構成されています。このモデルでは、特徴量の数が非常に多いため、過学習のリスクがあります。この企業の機械学習エンジニアは、過学習を防ぎ、モデルの汎化性能を向上させるために適切な正則化手法を適用することを検討しています。
>
> 以下のハイパーパラメータのうち、L2 正則化を適用して重みの大きさを抑制し、過学習を防ぐために設定すべき最適なパラメータはどれですか？

- A. learning_rate
- ✅ B. weight_decay
- C. batch_size
- D. dropout

**解説**:
weight_decay は重み減衰係数として知られる正則化パラメータであり、モデルのトレーニングにおいて L2 正則化を適用する。正則化によりモデルの重みの大きさを制御することができ、過学習のリスクを軽減してモデルの汎化性能が向上する。Amazon SageMaker NTM における weight_decay は 0.0〜1.0 の浮動小数点値で設定でき、デフォルト値は 0.0（正則化なし）である。learning_rate はモデルが重みを更新する際のステップの大きさを決定するものであり、正則化や重みの抑制には関係しない。batch_size はトレーニング時に使用するデータポイントの数であり、過学習の抑制には関係しない。dropout はニューロンをランダムに無効化することで過学習を防ぐ手法だが、L2 正則化（重みの大きさを抑える）とは異なるメカニズムである。

## 問題11
> あるアプリケーションベンダー企業が、Web サーバー上のログをリアルタイムで収集し、処理するシステムを構築しています。この企業は、ログデータを 60 秒おきに取得し、さらにデータを Amazon S3 に保存する前に、データ形式を JSON に変換する必要があります。
>
> この要件を満たすために最適な構成はどれですか？

- ✅ A. Amazon Data Firehose を設定し、バッファリング間隔を 60 秒に設定し、データ変換に AWS Lambda 関数を使用します。
- B. Amazon Kinesis Data Streams を設定し、データを 60 秒間隔でバッチ処理し、AWS Glue を使用して JSON に変換します。
- C. Amazon Data Firehose を設定し、データを S3 に直接保存し、保存後に AWS Glue を使用して JSON に変換します。
- D. Amazon Data Firehose を設定し、バッファリング間隔を 0 秒に設定し、データ変換に AWS Lambda 関数を使用します。

**解説**:
Amazon Data Firehose はログデータをリアルタイムで取り込み、バッファリング間隔（0秒〜900秒）を指定することでデータをバッチ処理できる。要件では60秒ごとの処理が求められているため、バッファリング間隔を60秒に設定することで要件を満たす。さらに Data Firehose はデータ取り込み時に AWS Lambda 関数を組み込んで変換処理をサポートしており、取り込まれたデータを JSON 形式に変換できる。Kinesis Data Streams は60秒間隔のバッチ処理には追加設定が必要であり、Glue はリアルタイム処理に適していない。保存後に Glue で変換する方法では、保存前に JSON に変換するという要件を満たせない。バッファリング間隔を0秒に設定すると、要件の60秒間隔に適していない。

## 問題12
> ある銀行が Amazon SageMaker を使用して、社内の事務手続きや申請プロセスに関する問い合わせに対する FAQ ボットを作成しています。このモデルは、リクエストに対して数秒以内のレスポンスが求められます。ピーク時には秒間数百リクエストが発生しますが、非ピーク時にはリクエストがほとんど発生しません。ピーク時のトラフィック増加に対応するために、エンドポイントの計算リソースを自動的にスケールアウトする必要があります。
>
> 推論エンドポイントの可用性を維持しつつ、スケーリングを管理する要件を満たすために、どの機能を使用すべきですか？

- A. Amazon SageMaker バッチ変換エンドポイントを実装し、エンドポイントの自動スケーリングを有効にします。
- B. Amazon SageMaker 非同期推論を実装し、エンドポイントの自動スケーリングを有効にします。
- ✅ C. Amazon SageMaker リアルタイム推論を実装し、エンドポイントの自動スケーリングを有効にします。
- D. Amazon SageMaker リアルタイム推論を実装し、AWS Lambda 上にエンドポイントをデプロイします。

**解説**:
