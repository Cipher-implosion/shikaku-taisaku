## 問題1
**結果**: ✅正解

> あなたの会社では、複数の機械学習モデルを Amazon SageMaker で作成および管理しています。これらのモデルは、社内の複数の機械学習エンジニアによって管理され、必要に応じて更新されます。例えば、画像分析用のモデルAにはバージョン1.00, 1.01, 1.02 のように複数のバージョンがあり、売上予測用のモデルBにも複数のモデルがあります。この会社は、各モデルの複数のバージョンを中央管理したいと考えています。さらに、複数のモデルを集約して管理したいと考えています。この要件を満たす最適なソリューションはどれですか？

- ✅ A. SageMaker Model Registry でモデルグループを作成し、各モデルの複数のバージョンを管理します。複数のモデルグループをコレクションに追加します。
- B. Amazon S3 にモデルアーティファクトを保存し、メタデータを手動で管理します。
- C. Amazon SageMaker Feature Store を使用して、特徴量とモデルを同じ場所に保存し、複数のモデルを管理します。
- D. AWS Lambda 関数で各モデルのメタデータを動的に管理します。

**解説**:
SageMaker Model Registry は、モデルのバージョン管理を行い、トレーニングからデプロイメントまでのライフサイクルを追跡するために使用される。

モデルグループは、特定のモデルに関連する複数のバージョンを一元管理するための単位である。

コレクションは、複数のモデルグループを集約した単位である。異なるモデル間の管理や検索を効率化する。

選択肢Aは、モデルグループを作成して各モデルのバージョンを管理し、さらにコレクションにまとめることで、複数のモデルの中央管理を可能にする。これは提示された要件に最も適している。

- A. SageMaker Studio を使用して、モデルのパフォーマンスを手動で評価します。

推論レコメンデーション（デフォルトジョブタイプ）は、デフォルトのロードテストを使用して、推奨インスタンスタイプを短時間で特定する。

エンドポイントレコメンデーション（アドバンストジョブタイプ）は、カスタムトラフィックパターンや本番環境の要件に基づいたロードテストを実行し、より詳細な条件に基づいてインスタンスタイプの選定を行う。

## 問題3
**結果**: ❌不正解

> ある会社は、Amazon SageMaker を使用して推論モデルを構築しました。この会社は、モデルの予測がどのように生成されているのかをより深く理解し、各特徴量が予測結果に与える影響を定量化したいと考えています。これにより、モデルの透明性を高め、ビジネス上の意思決定に役立てたいと考えています。この要件を満たす最適な方法はどれですか？

- A. SageMaker Clarify で 部分依存プロット (PDPs) 分析を取得します。
- B. Amazon SageMaker Feature Store を使用して、各特徴量の重要度を計算します。
- C. Amazon SageMaker Model Monitor を使用して特徴量の影響を評価します。
- ✅ D. SageMaker Clarify で SHAP（SHapley Additive exPlanations）値を取得します。

**解説**:
SageMaker Clarify は、機械学習モデルの解釈可能性を向上させるためのツールである。モデルの予測において各特徴量がどの程度影響を与えるかを定量化するために SHAP 値を計算する。

SHAP 値 (SHapley Additive exPlanations) は、特徴量が機械学習モデルの予測に与える影響を定量化するためのフレームワークである。SHAP はゲーム理論に基づいており、各特徴量の「貢献度」を算出する。

部分依存プロット (PDPs) は、単一の特徴量と予測結果の関係を可視化するものであり、SHAP 値のように特徴量の全体の影響を示すものではない。本問では、「各特徴量が予測結果に与える影響を定量化する」必要があるため、PDPs でなく SHAP を用いるのが適切である。

## 問題4
**結果**: ❌不正解

> ある会社は、自社で管理している Amazon VPC のプライベートサブネットに SageMaker インスタンスをデプロイしました。今後、このインスタンスを関連会社に共有するため、外部への通信を可能にしたいです。一方、SageMaker インスタンスは最小限のアクセスのみを許容し、インバウンドトラフィックは拒否したいです。この要件を最小の運用オーバーヘッドで満たすために、最適な方法はどれですか？

- ✅ A. パブリックサブネットに NAT Gateway を設置し、SageMaker インスタンスの配置されているプライベートサブネットからのルーティングを設定します。
- B. SageMaker インスタンスが含まれる VPC にインターフェイス VPC エンドポイントを作成します。

- D. Amazon CloudFront ディストリビューションを作成し、SageMaker インスタンスの計算結果を配信します。

**解説**:
NAT Gateway は、外部（インターネット空間）から AWS 環境へのトラフィックを送信するため、グローバル IP アドレスをプライベート IP アドレスに変換する機能を提供する。

パブリックサブネットに NAT Gateway を設置し、プライベートサブネット内の SageMaker インスタンスがインターネットにアクセスするようにルーティングを設定することで、外部通信を可能とする。また NAT Gateway はインバウンドトラフィックを許可しないため、安全な通信が可能となる。

## 問題5
**結果**: ❌不正解

> ある学習プラットフォーム提供者は、学生の質問に対して適切な応答をするためのモデルを構築しています。この会社がモデルのプロトタイプモデルを使って概念実証を行った結果、適切な応答が返ってこないというネガティブなレビューが多く見受けられました。評価の低かった質問と応答の組み合わせを収集して分析したところ、質問内容が曖昧であり、最適な応答が得られていないことが分かりました。例えば、「数学の勉強方法を教えてください」のような抽象的な質問が頻出しています。プラットフォーム提供者は、教育コンテンツのデータセットに詳細なラベリングを行い、さらに質問の明確化を促す仕組みを検討しています。どのアプローチが最適ですか？

- ✅ A. インストラクションベースのファインチューニングを実行します。プロンプトテンプレートを用意して、質問のカテゴリを詳細にフィルタリングします。
- B. 教育データセットを増強して、既存の質問と回答のペアを拡大し、データの多様性を向上させます。
- C. SageMaker Clarify を使用して質問の曖昧さを検出し、モデルの予測に影響を与える特徴量を分析します。
- D. Amazon Comprehend を使用して質問の内容を自動ラベリングし、カテゴリ分けされたデータセットを生成します。

**解説**:
曖昧な質問への適切な応答を行うためには、質問を詳細なカテゴリに分けて扱うことが効果的である。インストラクション（命令）ベースのファインチューニングを実行し、プロンプトテンプレートを作成することで、モデルに質問の意図をより具体的に理解させることができる。この方法は、モデルの予測精度を向上させ、曖昧さを減少させるのに最適である。

## 問題10
**結果**: ✅正解

> 東京に拠点を置くグローバルな小売企業があります。この企業は、複数の特徴量を使用して売上（目的変数）を予測する機械学習モデルを構築しています。売上データはさまざまな決済通貨（EUR、USD など）を JPY に統一して管理していますが、JPY に変換された数値は非常に大きな桁数になるため、そのままではモデルが高い値に引っ張られ、正確な学習が妨げられる可能性があります。この問題を解決するために、データに適用すべき変換方法はどれですか？

- A. 標準化（Standardization）
- B. 正規化（Normalization）
- C. 平均値によるセンタリング
- ✅ D. 対数変換

**解説**:
対数変換は、数値のスケールを小さくし、大きな桁数の特徴量がモデルに過剰な影響を与えるのを防ぐための方法である。売上データのように数値の分布が偏っている場合、対数変換により分布を正規分布に近づけることができる。これにより、モデルがより正確にデータのパターンを学習できる。

## 問題11
**結果**: ❌不正解

> ある会社では、Amazon S3 バケットに格納されたデータセットを用いて機械学習タスクを実行しています。この会社のセキュリティポリシーでは、すべてのデータを暗号化することが義務付けられています。また、暗号化に使用するキーは、自社で作成し、管理し、定期的にローテーションする必要があります。この要件を満たすための最適なアプローチはどれですか？

- A. Amazon S3 サーバーサイド暗号化をデフォルト設定で有効化します。
- B. AWS Key Management Service (KMS) でデフォルトの AWS 管理キーを使用します。
- C. AWS CloudHSM を使用してキーを生成・管理します。
- ✅ D. AWS KMS にカスタマーキーをアップロードします。手動でローテーションを実行します。

**解説**:
本問では、暗号化キーを自社で作成およびローテーションする必要があるため、AWS 管理キーは使用できない。Amazon S3 のデータをカスタマーキーで暗号化するには、AWS Key Management Service (KMS) を使用する必要がある。

自社で作成した暗号化キーを使用するためには、AWS KMS にカスタマー管理キーをアップロードする必要がある。また KMS にアップロードしたカスタマー管理キーは、手動でローテーションする必要がある。AWS 管理キーは自動ローテーションがサポートされているが、本問では「自社で～定期的にローテーションする」という記載があるため、AWS 管理キーは使用できない。

## 問題12
**結果**: ❌不正解

> ある企業では AWS CloudFormation テンプレートを用いて Amazon SageMaker インスタンスをデプロイしています。この会社は、同じモデルを複数の異なるリージョンにデプロイするためにテンプレートを活用しています。一方、リージョン毎にデータ量やトラフィックが異なり、インスタンスタイプを変える必要があります。この会社は、各リージョンの開発者がデプロイ時にインスタンスタイプを選択できるようにしたいと考えています。この要件を満たすために、CloudFormation テンプレートのどの部分を変更すればよいですか？

- ✅ A. Parameter
- B. Resource
- C. Mappings
- D. Conditions

CloudFormation テンプレートの Parameter セクションを使用することで、テンプレートをデプロイする際にユーザーがインスタンスタイプを指定できるようになる。これにより、同じテンプレートを異なる要件に基づいてカスタマイズできるようになる。

Mappings セクションは、特定のリージョンに基づいて固定値を定義するセクションであり、ユーザーが動的にインスタンスタイプを選択することはできない。Conditions セクションは特定の条件に基づいてリソースの作成や構成を制御するものであり、デプロイ時にユーザーが直接値を入力するような動的な操作には適していない。

## 問題14
**結果**: ✅正解

> ある会社では、Amazon S3 バケットにトレーニング用のデータを保存しています。これらのデータは、同社の基幹システムから毎日抽出され、日付ごとにプレフィックス化された S3 バケットに保存されます。しかし、1年以上前の日付のデータはほとんどアクセスされず、機械学習タスクに使用されることもありません。この会社は、これらのデータのストレージコストを最適化したいと考えています。なるべく少ない運用オーバーヘッドでこれらの要件を満たす適切なソリューションを選択してください。

- ✅ A. 1年間アクセスがないデータを S3 Standard から S3 Glacier Archive に移行するライフサイクルポリシーを作成します。
- B. S3 Intelligent-Tiering を使用し、データアクセスパターンに基づいてデータを自動で移行させます。
- C. S3 One Zone-IA を使用し、1年以上前のデータを低頻度アクセスストレージクラスに移行します。
- D. データを Amazon Elastic File System (EFS) に移行して、長期間保存します。

**解説**:
S3 Glacier Archive は、長期間アクセスされないデータを低コストで保存するためのストレージクラスである。ライフサイクルポリシーを設定することで、1年以上アクセスされないデータを自動でアーカイブに移行し、保管コストを削減できる。

S3 Intelligent-Tiering はアクセス頻度に応じてデータを自動的に適切なストレージクラスに移行するが、本問の場合、1年という具体的な要件が提示されているためライフサイクル管理を使用して S3 Glacier Archive に移行する方法の方がよりコスト効率が高い。
