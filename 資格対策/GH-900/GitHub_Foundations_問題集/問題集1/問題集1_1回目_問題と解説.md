## 問題1
**secret gist を最も正確に説明している記述は次のうちどれですか？**

- gist の URL を知っている人なら誰でも gist を表示できる ✅（正解）
- secret gist には GitHub Enterprise が必要である
- gist Discover ページから誰でも gist を見つけられる
- アクセス権を割り当てられたユーザーだけが gist を表示できる

**解説**
secret gist は、公開一覧には出さずに共有 URL を知っている人へ見せるための gist です。完全なアクセス制御付き private リポジトリとは性質が異なります。gist は短いコード片やメモを共有するための Git リポジトリで、public gist は Discover などで見つけられますが、secret gist は検索されにくく、URL を持つ相手に共有する前提で使います。

参照: [Gist の作成 - GitHubドキュメント](https://docs.github.com/ja/get-started/writing-on-github/editing-and-sharing-content-with-gists/creating-gists)

**GitHub 承認済みベンダーが提供する既存の action を見つけるには、何をすべきですか？（2つ選択）**

## 問題8

## 問題22
**Organization settings から、Organization owner は GitHub Actions の利用にどの制限を設定できますか？（3つ選択）**

- self-hosted runner を使用する action を許可する
- Codespace から action を実行できるようにする
- 指定した action を許可する ✅（正解）
- Marketplace verified creator による action を許可する ✅（正解）

self-hosted runner に関する設定は [Runners] セクションで扱う別の設定であり、Codespace からの action 実行も Actions ポリシーの選択項目ではありません。

## 問題24
**分散型バージョン管理システムを最もよく説明しているものはどれですか？**

- 中央サーバーにプロジェクト履歴全体を保存し、開発者が編集用にファイルをチェックアウトするシステム
- プロジェクトファイルをクラウドベースのサーバーに保存し、複数の開発者が同じコードベースで同時に共同作業できるシステム
- 各開発者が、完全なプロジェクト履歴とメタデータを含むコードリポジトリ全体のローカルコピーを持つシステム ✅（正解）
- 開発者が命名規則や手動バックアップを使って、ファイルの異なるバージョンを手作業で追跡、管理する必要があるシステム

**解説**
分散型バージョン管理では、各開発者のローカル環境にもリポジトリ全体の履歴が存在します。Git はこの分散型モデルを採用しているため、中央サーバーに常時依存せずに履歴確認や branch 作業を行えます。

参照: [GitHubと Git について - GitHubドキュメント](https://docs.github.com/ja/get-started/start-your-journey/about-github-and-git#about-git)

## 問題25
**gist の履歴を保持しながら、別のユーザーの gist を基に public gist を作成する最も効率的な方法はどれですか？**

- gist を fork する ✅（正解）
- 新しい gist を作成し、既存 gist の内容をコピーする
- gist を clone する
- 既存 gist への追加を依頼する

**解説**
他のユーザーの gist を基に自分の gist を作成し、元の履歴も保ちたい場合は fork を使います。fork により、元 gist から派生したコピーを自分のアカウント側で管理できます。clone はローカルコピーを作る操作であり、GitHub 上に自分の public gist を作成する操作ではありません。

参照: [Gistのフォークとクローン - GitHubドキュメント](https://docs.github.com/ja/get-started/writing-on-github/editing-and-sharing-content-with-gists/forking-and-cloning-gists)
