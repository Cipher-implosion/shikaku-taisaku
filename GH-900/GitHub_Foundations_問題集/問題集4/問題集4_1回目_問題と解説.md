## 問題1
**次の GitHub 構文形式のうち、対応するテキストと一致しているものはどれですか？**

- * This is a heading
- This is a link
- HTML コメントの開始記号と終了記号で This is a comment を囲む ✅（正解）
- This is bolded text
- 1 This is an ordered list

**解説**
GitHub Flavored Markdown では、見出し、リンク、コメント、太字、順序付きリストにそれぞれ決まった書き方があります。This is a comment を HTML コメントの開始記号(`<!--`)と終了記号(`-->`)で囲むと、Markdown内のコメントとして扱われ、通常の表示結果にはレンダリングされません。アスタリスクは見出しではなく順序なしリスト、単なるテキストはリンク構文を欠き、`**`や`__`を欠くテキストは太字にならず、数字の後にピリオドがない場合は順序付きリストとして成立しません。

参照: [基本的な書き込みと書式設定の構文 - GitHubドキュメント](https://docs.github.com/ja/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)

## 問題2
**GitHub ユーザーとしてアカウントのセキュリティを強化するために、UI のどこで two-factor authentication (2FA) を設定できますか？**

- Profile -> Account -> 2FA
- Repository Settings -> Secrets and Variables -> 2FA
- Organization Settings -> Authentication Security -> 2FA
- Settings -> Password and Authentication -> 2FA ✅（正解）

**解説**
GitHub アカウントの 2FA は、個人アカウントの Settings 内にある Password and authentication から設定・管理します。Repository Settings の Secrets and Variables はリポジトリのシークレット管理、Organization Settings は組織の認証ポリシー管理であり、いずれも個人アカウントの 2FA 設定画面ではありません。

## 問題3
**Git と GitHub の違いとして正しいものはどれですか？**

- Git は中央集権型バージョン管理システムであり、GitHub はクラウドベースの共同作業プラットフォームである
- Git はクラウドベースのホスティングサービスであり、GitHub は分散型バージョン管理システムである
- Git と GitHub は、バージョン管理と共同作業に使う同じツールの別名である
- Git はファイル変更を追跡するコマンドラインツールであり、GitHub は Git リポジトリで共同作業するためのプラットフォームである ✅（正解）

**解説**
Git はファイル変更を追跡するコマンドライン中心のバージョン管理ツールであり、GitHub はその Git リポジトリを保存・共有・レビュー・共同作業するためのクラウドプラットフォームです。Git は分散型であり中央集権型ではなく、GitHub はクラウドホスティングサービスであってバージョン管理システムそのものではありません。両者は同じツールの別名でもありません。

参照: [What is GitHub? - GitHubドキュメント](https://docs.github.com/ja/get-started/start-your-journey/about-github-and-git)

## 問題5
**Issue または Pull Request に複数のコラボレーターを割り当てると、どうなりますか？**

- main branch に変更を直接コミットし、pull request を省略できるため

- status checks が失敗していても変更を main branch にマージできるため
- default branch に取り込む前に変更をレビューし、status checks で問題を検出できるため ✅（正解）

**解説**
GitHub flow では、変更を feature branch で作業し、pull request でレビューと status checks による自動検証を行ってから default branch へマージすることで、default branch を直接変更せずに問題を発見できます。main branchへの直接コミット、レビューの省略、失敗したstatus checksを無視したマージは、この流れと一致しません。

参照: [GitHub flow](https://docs.github.com/ja/get-started/using-github/github-flow)

## 問題24
**GitHub アカウントを保護するために使用できる two-factor authentication (2FA) methods はどれですか？（3つ選択）**

- Authenticator app ✅（正解）
- Security questions
- GitHub Mobile ✅（正解）
- Security keys ✅（正解）
- Single sign-on

**解説**
GitHubアカウントの2FAでは、ワンタイムコードを生成するAuthenticator app、モバイルアプリを使ったGitHub Mobile、物理キーや対応デバイスを使うSecurity keysを追加認証として利用できます。Security questionsはGitHubの2FA方法ではなく、Single sign-onは組織やEnterpriseの認証統合であり、個人アカウントを保護する2FA方法そのものではありません。

参照: [2 要素認証を設定する - GitHubドキュメント](https://docs.github.com/ja/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication)

## 問題25
**Issue を見つけやすくするために Issues ページの上部へ追加する機能はどれですか？**

- Issue に Star を付ける
- Issue に Label を付ける
- Issue に Subscribe する
- Issue を pin する ✅（正解）

**解説**
重要な Issue を見つけやすくするには、Pin the issue を使ってリポジトリの Issue 一覧の上部に固定表示します。Star はリポジトリやプロジェクトへの関心表示、Label は分類やフィルター、Subscribeは通知を受け取るための操作であり、いずれも一覧上部への固定表示は行いません。

参照: [Issue をリポジトリにピン止めする - GitHubドキュメント](https://docs.github.com/ja/issues/tracking-your-work-with-issues/pinning-an-issue-to-your-repository)
