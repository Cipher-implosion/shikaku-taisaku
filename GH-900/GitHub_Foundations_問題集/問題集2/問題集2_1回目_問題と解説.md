## 問題1
**次のうち、ユーザープロフィールの contribution graph にカウントされるものはどれですか？（2つ選択）**

- 作成したコミット ✅（正解）
- 公開リポジトリ
- フォロワー
- クローズした Issue
- 作成した Pull Request ✅（正解）

**解説**
contribution graph は、プロフィール上でコミットや Pull Request などの貢献履歴を可視化する表示です。集計対象は実際の活動であり、フォロワー数や公開リポジトリ数のようなプロフィール属性は含まれません。Issue を閉じたこと自体は contribution graph の加点対象として明記されていません。

参照: [プロフィールでコントリビューションを表示する - GitHubドキュメント](https://docs.github.com/ja/account-and-profile/setting-up-and-managing-your-github-profile/managing-contribution-settings-on-your-profile/viewing-contributions-on-your-profile)

## 問題2
**GitHub flow では、Pull Request が承認されたときの主な操作はどれですか？**

- feature branch をマージする ✅（正解）
- 変更をデプロイする
- リリース用の Issue を作成する
- Git のタグを作成する

**解説**
GitHub flow は、短命ブランチで変更し Pull Request でレビューしてから既定ブランチへ統合する軽量な開発フローです。承認後の中心操作は変更をマージして共有することであり、デプロイやタグ付けはその後の工程として任意に行います。

参照: [GitHub flow](https://docs.github.com/ja/get-started/using-github/github-flow)

## 問題5
**次のうち、Git の commit を最も適切に表しているものはどれですか？**

- 特定時点のリポジトリ全体のスナップショットで、プロジェクト内のすべてのファイルの状態を記録したもの ✅（正解）
- Git で開発者が最後に行った変更の記録
- Git における 1 つまたは複数ファイルへの変更の集まり
- Git リポジトリ内のファイル変更の目的を説明するログメッセージ

**解説**
commit は、ある時点のリポジトリ全体の内容を識別可能な履歴として保存する Git の基本単位です。単なる変更メモではなく、後から特定時点へ戻れるスナップショットとして扱う点が本質です。（最後の選択肢は commit message の説明です。）

参照: [コミットについて - GitHubドキュメント](https://docs.github.com/ja/pull-requests/committing-changes-to-your-project/creating-and-editing-commits/about-commits)

## 問題15
**GitHub Projects でプロジェクト初期化時に既定で有効になっている workflow はどれですか？（2つ選択）**

- Issue にラベルが追加されたとき

## 問題16
**base permission が No permissions のとき、internal repository の可視性により、個別に招待されていなくても閲覧できるユーザーはどれですか？（2つ選択）**

- 同じ organization の outside collaborator

- 同じ organization のメンバー ✅（正解）

## 問題17
**Enterprise Managed Users (EMU) の制約として正しいものはどれですか？**

- organization の base permission を適用できない

## 問題24
**Pull Request、Issue、コミット履歴などのリポジトリアクティビティを確認できる Insights の機能はどれですか？**

- Traffic
- Activity overview
